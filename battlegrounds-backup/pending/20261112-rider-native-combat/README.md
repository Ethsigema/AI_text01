# 显眼的骑手：真实战斗接通（2026-11-12）

这是一批从已核验恢复副本继续开发的独立受限候选，包含上一批碎地者修复。没有找回不可见的原始工作树，未知的未上传修改仍无法排除。没有覆盖默认工程，没有删除旧备份，没有新增英雄或额外机制。保留纳迦、排除畸变怪，范围继续限定随从、酒馆法术和最近完整饰品。

## 实际实现

- 从已归档、尚无真实引擎运行证据的骑手候选导入原生 Catalog/Game/Combat 接线。使用当前已核对原始资料：普通 BG31_925、金色 BG31_925_G；亡语使己方存活纳迦获得 +2/+1 或 +4/+2，每 3 次本人施法提高一个基础单位。
- 只有实际 Game 发出的本轮权限、实际 Combat 的原始单位身份、自然死亡回执及当前亡语派发才允许计算。效果投影到原有 deathrattle_buff 分支，由原生属性写入函数提交，没有假写入器或新持久法术计数器。
- 修复真实 Catalog 给金色牌添加合法 pool_blocker 后被全卡来源校验误拒的问题；只允许原生准确注记，不放宽其他元数据。
- 两次真实整引擎尝试发现并复现 Invalid base_unit: rider_changed_unit_identity。原生 base_unit 是不含 kind 的十字段快照。现在 Combat 明确传 is_base_unit，仅该分支按原生完整快照精确比较，真实随从仍必须带 kind=minion。未使用“缺字段就当快照”的宽松判断。
- Game 结算返回时释放骑手本轮权限引用。Combat 保留一次原生释放，不残留重复清理代码。
- 校正归档候选“未安装、未执行引擎”的历史元数据，明确为有限真实验证片段，未宣称完整池验收。相关来源摘要随实际文件变化重新核验。

相对上一批已验证碎地者候选，新增 12 文件、修改 81 文件、删除 0；大量修改是受依赖影响的来源摘要钉值，不是声称新增同等数量玩法。完整变化表见 CHANGES_FROM_PREVIOUS_CANDIDATE.json。本增量相对第 14 批合并基线累积，已含所需碎地者修改，不需先叠加两个旧候选。

## 实际测试

Godot 4.6.3；完整原生 Game/Catalog/Combat；原艾德温、5 类原生随从家族及酒馆铸币的受限房间。测试卡通过原生工厂和入手函数加入，出牌、酒馆币施法、双方结束回合均走公开 apply_command。没有直接赋值法术计数、修改战队或替换属性写入器。测试卡的取得不代表已测试随机商店或三连。

11 个独立房间、291 项真实集成检查：

- 普通骑手施法 0/2/3/6 次时，每次亡语实际提交 +2/+1、+2/+1、+4/+2、+6/+3；金色对应 +4/+2、+4/+2、+8/+4、+12/+6。
- 普通提图斯·瑞文戴尔使亡语真实重复 2 次；金色重复 3 次。逐次属性提交与累积攻击值一致，没有把重复数乘算两遍。
- 对手施法 6 次而本方 0 次，本方骑手仍是 +2/+1。
- 骑手确实自然死亡；只给本方仍存活的纳迦提交加成，自己和非纳迦提图斯不受益。
- 战斗加成不错误写回招募战队；所有用例真实完成战斗并进入第 2 回合；Game 骑手权限引用清空。

## 明确限制

- 仅允许原艾德温、骑手/迷你侍从/乘波骑士/碎地者/提图斯的普通与金色原生战队。默认完整房间不是本轮验收对象。
- 含骑手的战斗暂不支持临时层、附加组件、复制/变形/复生、其他英雄、任务/饰品、幽灵、其他原生随从家族等交叉组合，现有门禁仍明确拒绝。
- 战斗中的玩家施法历史非空仍被明确拒绝。本轮验证的是招募阶段真实施法计数，不把它扩称为战斗中施法成长已支持。
- 未验证随机商店获取、三连、完整对局、旧存档、所有卡牌组合，也没有新增饰品整类验收名额。可靠整类完成率仍未知。本轮没有重新核实全体最新卡池资料。
