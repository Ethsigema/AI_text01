# 第六批：五项历史工具边界审查，仅封存证据

## 结论

本批未形成新的游戏源码恢复候选，新增、修改、删除游戏文件均为 0。五个历史工具的原件、安装 SHA 和原始交接 ZIP 成员一致，RAW/EXPECTED 也与当前来源一致，但历史离线编译器与当前来源的依赖准入边界不同，因此全部暂缓恢复。

输入固定版本为 `3d41c7f71bdda146ed37930c7591b419b53e36a6`。沿用 Devourer 后的完整逻辑源码清单，SHA256 为 `9baabc104b5f2f93087dfec0e385d6cb9fceffbf3b1d4441ec91da463a727260`，27,912 项。本包的 BASE_MAP.json 是这份清单的逐字节副本，没有新的 SOURCE_MAP.json 或 delta。

原 367 项引用范围仍有 **353 项未恢复**，其中原 68 项单历史版本类别仍有 55 项未恢复。此前六项暂缓对象保持不变，本次再明确五项暂缓对象；这不是对全工程所有缺口的统计。

## 五项结果

- Temperance：历史工具要求演示英雄 BG32_HERO_001；当前本地来源没有 DEP_RAW，TARGET_IDS 的注释明确该英雄不构成运行时依赖。
- Everything on Fire：历史工具要求 BG32_HERO_001；当前来源闭包仅约束自身，注释明确历史英雄不是普通原生英雄、卡牌或机制的准入名单。
- Anti-Gravity：历史工具要求 BG32_HERO_001、BG_GVG_085、BG_GVG_085_G；当前本地 DEP_RAW 保留两张随从原文，当前 closure_error 不要求三项演示对象存在。
- Anomalous Twins：历史工具要求同上三项；当前本地 DEP_RAW 的两张随从仍逐字段一致，当前闭包明确不拥有特定英雄或候选随从身份。
- Clockwork Stadium：历史工具要求同上三项；两张本地随从原文一致，但当前闭包不以历史依赖样例为其他原生卡牌的准入依据。

五模块合计 11 个“模块-演示依赖”组合，仅涉及 3 个不同 ID。所有历史编译器在完整原始样例输入上仍产出当前 EXPECTED，且会拒绝每个样例依赖的缺失或改名。实际当前 Godot 来源闭包在上述样例全部缺失时仍通过，也忽略人为添加但改名的演示对象记录，同时继续拒绝自身来源记录的缺失或改名。

这证明的是两种校验的边界不同，不是运行时漏洞、游戏机制失效，也不证明历史编译器在完整工程中一定无法运行。其他原生对象由各自来源及运行时宿主负责，本次没有代替这些宿主作出全局判断。按照“差异暂缓”的要求，不将旧编译器放回当前 tools。

## 历史证据和功能用途

每项保留历史 Python 原文、integration_manifest.json、shared_manifest.json、存在的 FROZEN.json、当前来源原文、基线 ZIP 成员定位及 SHA。基线 ZIP 此次重新散列，并逐字节比较成员内容。基线 SHA256：`33b3a1a12185cf9035cec33da4fff7008c7680194eb045b37234fbb934803d65`。

五项共 105,845 字节历史原文。每项只有一个已知历史整体版本，没有找到后续修改补丁；这不等于证明它是最新安装版本。详细 SHA 和来源见 REVIEW_CONFIG.json、evidence/PRIOR_INVENTORY_ROWS.json。

五项 tools 路径都存在于当前来源 RUNTIME_PATHS，当前 Catalog 会把它们的文件哈希纳入指纹。当前文件本身不是这五模块的固定 PROOF_SHA256 准入 pin；实际 64 个模块级 pin 检查全部通过，即使五个工具路径仍缺失。历史 inventory 另有 Python 导入证据，原文实际有 compile_card 行为，因此不能简单称其为没有功能作用的指纹文件。

本次没有安装这些文件，故本次没有引入新的源码指纹变化。恢复任意历史工具可能改变指纹，不能据此承诺旧存档兼容。没有计算或运行完整 Catalog 的最终指纹。

## 低资源验证

- Python：87 项检查，AST 允许范围为字面常量、标准库 deepcopy、same 和 compile_card。只执行这五个独立原始模块的受限测试，不执行完整离线编译器。峰值 13,908 KiB，地址空间上限 128 MiB。
- Godot 4.6.3：两次独立输入目录重建，各 173 项检查，共 346 项断言；两份报告完全一致。实际来源 preload 闭包分别为 3、4、3、6、6 个脚本，未装载完整 Catalog 或 Game。峰值分别 75,472、75,348 KiB。
- 静态完整性：60 项检查，包含原始 SHA、当前源码清单对应关系、探针输入和执行脚本未变、五项目标仍缺失、独立复现及 353 项未恢复列表。
- 每次 Godot 串行执行，RSS 达 192 MiB 停止，AS 上限 2 GiB，启动前要求 1 GiB 可用内存，系统可用内存低于 640 MiB 停止，45 秒超时。两次正常退出，无 Godot 错误或受控中断。

MiniCatalog 仅提供来源闭包所需的 get_card 与 source_catalog，是测试夹具，不是真正完整 Catalog。project.godot 同样是独立的最小探针项目。

## 已保留的初始检查失败

1. 初版 Python 检查误以为所有历史依赖仍应在当前模块的 DEP_RAW 中，Temperance 首先触发断言。实际是演示英雄没有当前本地 DEP_RAW 条目，而非同一条目内容改变。保留原脚本和 INITIAL_PYTHON_ASSUMPTION.json，最终报告明确区分缺失的本地条目与相同的现有条目。
2. 初版完整性检查误把新建的最小 project.godot 与原游戏 project.godot 要求同 SHA。保留原脚本和 VERIFIER_SYNTHETIC_PROJECT_NOTE.json，最终检查仅对这个明确的测试夹具使用预期头部验证，所有原始来源及证明文件仍严格对照固定清单。

以上均发生于新增的审查文件，没有修改原始工具、游戏源码、历史备份或前批证据。失败不能计为通过。

## 独立复现

在新的目录解包，不覆盖任何已有目录。运行 `python3 prepare_probes.py`，然后 `python3 run.py review_again`。报告会写入一个新的 review_again 目录，不覆盖封存的原始报告。可执行 `python3 probe_python.py` 和 `python3 verify_review.py` 重验，但仅在独立解包副本上运行，因为它们会写对应结果 JSON。两份带 initial 名字的脚本保留初始错误，不应当成成功验证入口。

完整游戏、完整离线编译器、实际对局、旧存档和其他 353 项缺口均未验收。旧备份、旧截断包及此前候选全部保留。
