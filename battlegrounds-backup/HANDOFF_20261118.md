### 恢复操作

Python 3.12+；使用全新的、尚不存在的目标目录。先核对下载文件与 `SHA256SUMS.txt`，再在检查点文件所在目录执行：

```sh
python3 download_inputs.py --destination /your/path/new-inputs
python3 restore.py --inputs /your/path/new-inputs --workspace /your/path/new-restored
```

脚本会下载并验证全部固定依赖、恢复旧链、核对基线、应用本次差异/删除，再验证所有最终文件。任一下载失败、大小/哈希不符、缺分卷或源清单不一致，应停止；不要跳过断言或换成近似版本。

成功结果应在新恢复目录的 `RESULT.json`；工程位于 `new-restored/project/`。先确认文件数 28,394、无 missing/extra/mismatched，再尝试运行。保留恢复日志，避免把“脚本执行了”当作“验证成功”。

## 5. 工程结构与运行入口

已核实最新冻结工程结构：

- `project.godot`：Godot 项目入口，项目名“酒馆实验室 · 单机战棋”，4.6 特性、GL Compatibility 渲染。
- `main.tscn` → `ui/main.gd`：主场景与界面入口，1440×900 视口。
- `core/catalog.gd`：目录与卡牌加载/支持判定的重要入口。
- `core/game.gd`：招募、房间/命令等运行主流程入口。
- `core/combat.gd`：战斗主流程；大量 `*_host.gd`、`*_sources.gd` 等模块处理效果与严格来源校验。
- `data/`：原始与编译目录、作用域清单、补丁覆盖和证据注册数据，例如 `catalog_raw.json`、`catalog.json`、`current_scope_manifest.json`。
- `assets/`、`ui/`：素材与交互；`research/`：规则来源和来源闭包材料；`tests/`：测试、日志和对应源码哈希；`docs/`、`PROGRESS.md`：设计与进度说明。
- `tools/`：工程辅助脚本。

推荐沿用 Godot **4.6.3** 与 Python **3.12+**。先在可写 HOME/XDG 目录进行导入，再打开项目：

```sh
godot --headless --editor --path /your/path/project --import
godot --path /your/path/project
```

不要复制缺失 `.godot` 缓存作为修复；首次导入应生成缓存。测试命令以各批报告和对应测试脚本为准，不把旧日志当作对新改动的重跑结果。观察退出码和全部 ERROR/SCRIPT ERROR/WARNING，不能只看最后断言数。

## 7. 如果以后继续开发

1. 先决定采用远端已验证基线，还是取得全部未发布增量后采用最新云端冻结版；不要混合未知来源文件。
2. 完整恢复并逐文件核对，保留固定提交和所有依赖。再检查导入、启动、基础对局，记录当前实际错误。
3. 首先建立可维护的逐卡台账：稳定 ID、普通/金色、当前范围来源、完整/局部/未实现/待核、测试与代码哈希。先盘清范围，避免再次用注册量或测试次数当完成率。
4. 选一张规则证据明确的未完成卡，完成实际提供/购买/打出或施放/触发/死亡/出售/金色/三连等适用链路，再做必要交叉测试；优先闭环，避免长期只添加微小边界。
5. 修改 `core` 后检查精确来源闭包与哈希依赖。不能简单删除校验、改 `supported=true` 或清空保护来让测试变绿。
6. 历史卡自选可用与当前官方池是两件事。不要因修复历史卡就加入现役默认池，不要把尚未核实的金色规则猜成普通翻倍。
7. 每批冻结源码与测试，记录失败日志和最终通过日志、完整文件清单、差异及删除项。得到完整恢复证据以后再发布，不把备份成功报告为游戏完成。
